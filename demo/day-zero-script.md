# Video: "Start your Solana hackathon project on day zero" (≈3:00, @expertvagabond)

Voice: Matthew, first person, plain, problem first, no hype. Footage: the stockcurve console, the Clawpump dashboard, a
terminal, the day-zero checklist on screen. Numbers spelled out for TTS.

**0:00 · cold open (console on screen)**
"I just spent a week on the Stocklana hackathon. Fourteen pools on mainnet, four agent tokens, a launch page, a sponsor
replying to us in twelve minutes. It went fine. But about a third of the week went to things I should have done on the first
afternoon, before any code. This is that afternoon."

**0:25 · identity (X profile + mailbox on screen)**
"Start with a mailbox on a domain you own. Not your Gmail. Then the name: check the X handle, the GitHub name and the domain
in one sitting, because renaming a project mid-week means redoing the deck, the site and the repo. We did that. Make the X
handle for the project, and one for the agent if there is one, with that mailbox. Logo, avatar and banner once, from one
image. Every form you touch this week will ask for them."

**0:55 · keys (Clawpump dashboard on screen)**
"Sign up for every sponsor with that mailbox, and generate API keys from inside the dashboard you're going to use. Our Clawpump
key could launch tokens but couldn't touch the agent we built in their dashboard, because the key was never linked to that
account. That was a day. And read the sponsor's own dashboard before their docs. Clawpump had a one-click 'launch on
Meteora paired with a stock' button the whole time. We rebuilt it through the API first."

**1:30 · money (terminal: wallet balance history)**
"One project wallet, funded once, with a floor of one SOL you never spend. Congestion retries, rent, deposits, creation fees:
all of them hit when the wallet was at two hundredths. And decide what gets rent before you launch anything. We launched
thirteen demo pools. Two SOL, almost all of it account rent that can never be closed. One pool with a post behind it would
have taught the same thing."

**2:00 · the submission plan (tracks row on screen)**
"Before building, write one sentence per track naming the thing a judge will click. Build those six things first. Then a
live page that shows them. Then reply on every sponsor's post with what's live, the day it's live. That reply is how a sponsor
ended up describing our stack, accurately, in public, and it's in the submission."

**2:35 · verify (terminal: a read-back)**
"Last one. Read every claim back from chain before you write it down. We caught a 'plus twenty-one percent' exit that
actually lost money, and a stat in our own README that was wrong, only because we checked."

**2:50 · close (checklist on screen)**
"Mailbox, name, handles, logo, repo, linked keys, a wallet with a floor, one artifact per track, a live page, sponsor replies.
Then build. The checklist is in the repo. Link below."
