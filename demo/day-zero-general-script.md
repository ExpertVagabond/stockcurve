# Video: "Before you build on Solana" (≈2:45, @expertvagabond, general audience)

Voice: first person, plain, problem first, no hype, no project names. Footage: a blank X signup, a dashboard "API keys"
page, a wallet balance, a repo with a clean first commit, a checklist. Numbers spelled out for TTS.

**0:00 · open**
"Every Solana hackathon I've done, I lost the first two days to the same things. None of them were code. This is the
afternoon you should spend before you write any."

**0:15 · identity**
"One mailbox on a domain you own. Not your Gmail. Then the name: check the X handle, the GitHub name and the domain in one
sitting, because renaming after launch means redoing the site, the deck, the repo and every sponsor form. Make the X
handle for the project, and a second one if a bot will post. One developer app covers all of them. Logo, avatar and banner
from one image, once. Every form this week will ask."

**0:45 · repo**
"Create the repo empty and decide public or private now. Gitignore before the first commit: node modules, env, output.
Secrets live in your config folder, never in the tree, never in a doc, never in a video. And a status file from day one:
done, next, the exact next command. When you get cut off, you resume instead of restart."

**1:10 · keys**
"Sign up for every sponsor and every data feed with that mailbox. Generate API keys from inside the dashboard you'll
actually use. A key from a docs-page form can be unlinked from your account. It works for some routes and returns four
oh three on the rest, and you find out mid-build. Read the sponsor's dashboard and pinned posts before their docs. The
button you're about to rebuild usually exists. And ask for entitlements on day one. They take days. The ask takes minutes."

**1:45 · money**
"One project wallet, funded once, with a floor of one SOL you never spend. Rent, congestion retries, creation fees and
deposits all arrive at the wrong moment. Know what can't be undone before you sign: locked liquidity, permanent configs,
rent that never closes. Demo scale doesn't make it cheaper. And the project wallet does not trade."

**2:10 · plan, talk, verify**
"Before building, write one sentence per track naming the thing a judge will click. Build those first. Put a live page in
front of them by day two. Reply on every sponsor's post the day something is live; they do answer, and their words end up
in your submission. And read every claim back from chain before you write it down. The ones that sound best are the ones
to check twice."

**2:35 · close (checklist on screen)**
"Mailbox, name, handles, logo, repo, linked keys, a wallet with a floor, one artifact per track, a live page, sponsor
replies. Then build. Checklist in the link."
